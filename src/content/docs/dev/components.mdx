## Asides and answers

:::tip[Practical advice]
Start with the simplest limit that protects you.
:::

:::caution[Common mistake]
Counting requests per server instead of per client.
:::

:::danger[Outage risk]
A retry loop with no backoff turns one slow dependency into a full outage.
:::

:::note[From the trenches]
Teams usually discover their real limits during their first big sale.
:::

<details>
<summary>1. What happens if the queue is unbounded?</summary>

Latency grows without limit instead of requests being rejected, and memory eventually runs out.

</details>

| Option | Accuracy | Memory |
|---|---|---|
| Fixed window | Low at boundaries | One counter |
| Sliding log | Exact | One timestamp per request |
