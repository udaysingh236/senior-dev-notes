# Kickoff prompt (run once)

Open the repo folder in VS Code with Claude Code, pick Opus with `/model`, and paste everything
below the line as your first message.

---

We're building a static learning site that teaches system design to beginners. Read `CLAUDE.md`,
`CURRICULUM.md` and every file in `.claude/skills/add-topic/` first. They are the spec.

Before writing any code, ask me for anything you need that isn't already set:
the site name, my GitHub username and repo name (or read them from `git remote -v`), and whether
I'll use a custom domain. Then fill the `<SITE_NAME>`, `<GITHUB_USER>/<REPO>` and `<SITE_URL>`
placeholders in `CLAUDE.md`.

Then set up the project. Check the current Astro and Starlight docs as you go rather than relying on
memory, since config details change between versions.

1. **Scaffold** Astro + Starlight in this folder (the Starlight template), keeping the existing
   `CLAUDE.md`, `CURRICULUM.md`, `KICKOFF.md`, `README.md` and `.claude/` intact.
2. **Configure** `astro.config.mjs`:
   - `site` set to the custom domain if I have one, otherwise the Netlify URL; no `base` path
   - sidebar: one group per track in `CURRICULUM.md` order, each autogenerated from its folder
   - GitHub social link, "edit this page" link, last-updated dates
   - custom CSS at `src/styles/custom.css`
3. **Content schema**: extend Starlight's docs schema with `tagline`, `difficulty`, `track`,
   `prerequisites`, `next` and `lastReviewed` (see `template.mdx` frontmatter).
4. **Theme**: a clean, readable look with good typography for long reading. Define the `--viz-*`
   tokens from `visuals.md` for light and dark mode.
5. **Shared components** in `src/components/`:
   - `TopicHeader` (override Starlight's page title area): tagline, difficulty badge, reading time
     computed at build time, prerequisite chips that link to published pages
   - `Figure` (caption, tap to enlarge on mobile)
   - `StepThrough` (per `visuals.md`)
   - `sim/SimShell` plus a seeded RNG and small helpers (per the contract in `visuals.md`)
   - `NextTopics` (resolves slugs to page URLs; unwritten topics show "coming soon")
6. **Pages**:
   - landing page: hero, who it's for, how to read a topic page, one card per track with
     published/planned counts, and the starter path from `CURRICULUM.md`
   - `/roadmap/`: every planned topic, grouped by track, generated from `CURRICULUM.md` if practical
   - `/about/`: who writes it, how pages are made (researched and drafted with AI assistance,
     reviewed by me), and how to suggest a topic
7. **Deploy**: keep the existing `netlify.toml`, and set its `NODE_VERSION` to the version the
   installed Astro requires. Add a `.gitignore`. Don't add a GitHub Actions deploy workflow;
   Netlify builds the site itself.
8. Run `npm run build` and fix everything until it passes. Commit as `chore: scaffold site` and push.
   Then walk me through connecting the repo on Netlify (Add new site → Import from GitHub → pick
   the repo; the build settings come from `netlify.toml`). Once I share the Netlify URL, set
   `site` in `astro.config.mjs` and `<SITE_URL>` in `CLAUDE.md` to it, commit and push.
   When I buy a custom domain later, walk me through adding it in Netlify (Domain management) and
   the DNS records at my registrar, then update `site` and `<SITE_URL>` to the new domain.
9. Stop there. I'll start a fresh session and run the pilot topic myself with
   `/add-topic Rate Limiting`.
